# 项目路线图

学习 Go 后端不能只靠语法练习，必须尽早进入项目主线。

项目路线的目标是：每个阶段都能产出一个可运行、可讲述、可复盘的成果。

## 项目设计原则

- 小步可交付，不做一上来就过大的系统
- 每个项目都对应一批明确能力点
- 优先选择后端常见能力：HTTP、JSON、配置、数据库、并发、测试
- 项目逐步升级，而不是每次完全推倒重来

## 项目主线建议

### 项目 1：Todo API

定位：第 1 个月主项目。

目标能力：

- Go 基础语法落地
- 标准库 HTTP 使用
- JSON 编解码
- 路由和请求处理
- 错误返回和简单分层
- table-driven tests 入门

最小功能：

- 创建任务
- 查询任务列表
- 查询单个任务
- 更新任务状态
- 删除任务

建议边界：

- 先用内存存储
- 不要一开始接数据库
- 先把 handler、service、store 的责任边界做清楚

### 项目 2：Blog 或 User Service

定位：第 2 到 3 个月过渡项目。

目标能力：

- 数据库接入
- 配置管理
- 日志和中间件
- 分层和依赖注入
- 基础接口设计

### 项目 3：带并发场景的业务服务

定位：中期强化项目。

目标能力：

- goroutine 和 channel 使用
- context 超时与取消
- worker pool 或任务处理模型
- 并发安全问题定位

### 项目 4：可展示的综合项目

定位：求职前主打项目。

目标能力：

- 工程结构完整
- 文档齐全
- 有测试和基础性能说明
- 能体现你的后端设计能力和 Go 特性理解

## 第 1 个月项目推进方式

第 1 个月不要把重点放在“做很多功能”，而是放在“建立正确骨架”。

推进顺序建议：

1. 搭环境和模块
2. 写最小 HTTP server
3. 处理 JSON 请求与响应
4. 完成 Todo 的增删改查
5. 补错误处理和返回格式
6. 补基础测试
7. 做一次结构整理和项目复盘

## 每个项目都要留下什么

每个项目至少留下以下成果：

- 可运行代码
- README 说明
- 关键设计说明
- 已知问题和后续优化点
- 一次项目复盘

## 判断项目是否真的有价值

一个学习项目只有同时满足以下条件，才值得写进简历：

- 你能独立讲清楚架构和实现
- 你能说明遇到过什么问题、如何解决
- 你能说出下一步如何改进
- 代码结构不是临时拼凑，而是具备最小可维护性

## 当前结论

先把 Todo API 做扎实。不要急着堆技术栈。第 1 个项目的真正目标不是炫技，而是建立 Go 后端的代码手感和工程基本盘。
