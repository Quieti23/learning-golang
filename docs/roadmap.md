# 学习路线图

这条路线不是按“知识点大全”设计，而是按“找 Go 后端工作需要具备什么能力”来设计。

## 总目标

把 Java 后端经验迁移到 Go 后端岗位能力，最终达到以下状态：

- 能独立开发和维护一个中小型 Go 服务
- 熟悉 Go 常见工程写法和调试方式
- 能理解并发、上下文、接口、错误处理等核心机制
- 能完成一个有一定工程感的项目并清楚说明设计取舍
- 能应对 Go 后端常见面试问题

## 路线分阶段

### 阶段 1：建立 Go 基础与最小项目能力

目标：用最短时间脱离“只会看不会写”的状态。

重点：

- 环境、工具链、模块、包管理
- 基础语法、struct、method、interface
- 错误处理、defer、panic、recover 的边界
- slice、map、pointer、value semantics
- JSON、文件、标准库 HTTP
- 小型 Todo API

验收：

- 能从零写一个小型 HTTP 服务
- 能读懂基础 Go 项目结构
- 能写基础单元测试

### 阶段 2：写出更像后端服务的代码

目标：从“能跑”进入“可维护”。

重点：

- 分层设计与依赖组织
- 配置管理、日志、错误码、参数校验
- 数据库访问、事务、连接池
- 中间件、上下文传递、超时控制
- 基础性能意识

验收：

- 完成一个带数据库的 CRUD 服务
- 能解释包划分和依赖方向
- 能处理常见接口设计问题

### 阶段 3：Go 并发与服务治理基础

目标：掌握 Go 作为后端语言的核心竞争力。

重点：

- goroutine、channel、select
- mutex、waitgroup、context
- 并发错误、资源泄露、竞态条件
- 服务超时、取消、重试、限流基础
- profiling、pprof、benchmark 基础

验收：

- 能写和读常见并发代码
- 知道什么时候不用 channel
- 能定位基础性能和并发问题

### 阶段 4：工程化与就业准备

目标：把学习产出转成可展示、可面试、可投递的成果。

重点：

- 完整项目打磨
- 项目 README、架构说明、接口说明
- 面试题整理与模拟表达
- 常见框架与生态认知
- 简历项目叙述和亮点提炼

验收：

- 至少 2 个可展示项目
- 一套 Go 后端面试笔记
- 能清晰表达 Java 转 Go 的优势与差异理解

## 节奏建议

基于每天 2 小时，建议采用以下节奏：

- 工作日：60 到 90 分钟编码，30 到 60 分钟看资料和复盘
- 周末：做周总结、补练习、整理笔记、修正计划

## 每阶段判断标准

只有同时满足以下三个条件，才算真的完成：

- 写得出来：能独立实现
- 说得清楚：能解释为什么这么写
- 改得动：能对已有代码做修改和优化

## 不建议的学习方式

- 长时间只看视频不写代码
- 语法学太久才开始做项目
- 用 Java 习惯生搬硬套 Go
- 一开始追求复杂框架和高级特性
- 没有阶段验收就不断往后学

## 当前建议

先完成第 1 个月，再决定第 2 个月细化内容。当前阶段的核心不是“学完 Go”，而是尽快形成 Go 后端的最小工作能力。
