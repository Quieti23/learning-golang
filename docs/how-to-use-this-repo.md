# 这个仓库怎么用

这个仓库不是资料收藏夹，而是学习执行系统。

你的目标不是每天看完多少内容，而是每天留下明确产出，并且知道明天接着做什么。

## 日常使用流程

每天打开仓库时，按这个顺序：

1. 看 `plans/month-01/README.md`，确认本周目标和今天任务。
2. 在 `demos/` 或 `exercises/` 写当天的最小代码。
3. 如果当天任务属于项目推进，就在 `projects/` 中完成对应改动。
4. 学完后，在 `progress/` 中记录今天完成了什么、卡在哪里、明天做什么。
5. 如果遇到明显误区或易错点，补到 `docs/common-pitfalls.md` 或自己的笔记里。

## 每天 2 小时推荐切法

### 模式 A：工作日标准版

- 20 分钟：阅读当天主题与已有笔记
- 70 分钟：动手写代码
- 20 分钟：整理问题、总结、提交进度
- 10 分钟：预告明天的起点

### 模式 B：状态一般时的保底版

- 15 分钟：回顾昨天内容
- 45 分钟：只做一个最小练习或修一个点
- 20 分钟：记录问题与收获

保底版的意义是不断档。连续性比单日强度更重要。

## 本仓库各目录怎么配合

- `plans/` 决定学什么
- `docs/` 解释为什么这么学、怎么判断学会了
- `demos/` 验证单点知识
- `exercises/` 做刻意练习
- `projects/` 把零散知识串成实际能力
- `progress/` 负责记录完成情况与复盘
- `interview-notes/` 把学习内容沉淀成可表达的知识

## 每天最小交付标准

每天至少完成以下四项中的三项：

- 一段可运行代码
- 一条关键知识总结
- 一个未解决的问题
- 一条明天的具体任务

如果四项都没有留下，当天通常等于“看过了，但没有真正学到”。

## 每周如何复盘

每周末使用 `docs/review-template.md` 做一次复盘，重点回答：

- 这周我真正会写了什么
- 哪些点还是 Java 思维在主导
- 哪些内容学过但还不能独立写
- 下周最优先补什么

## 什么时候可以进入下一阶段

不要因为计划写完了就进入下一阶段，要看是否达到完成定义：

- 能独立完成本阶段最小项目
- 能不用照抄写出主要代码骨架
- 能解释核心概念和取舍
- 能指出至少 3 个本阶段常见坑

## 如何处理卡住的情况

如果某个点连续 2 天卡住，按下面处理：

1. 缩小任务，不要继续硬啃整块内容。
2. 用 demo 先验证最小可运行示例。
3. 用 Java 对照法理解差异。
4. 把问题写成一句具体问题，而不是“这里不懂”。
5. 如果还不通，先记录并继续主线，不在细枝末节上失速。

## 这个仓库要长期沉淀什么

随着学习推进，这个仓库应该逐步沉淀为：

- 你的 Go 学习路径记录
- 你的项目样本库
- 你的面试知识库
- 你的错误清单和复盘清单

如果一个仓库不能帮你快速进入今天的任务，也不能帮你看见自己的进展，那它就还不是一个真正可用的学习系统。
