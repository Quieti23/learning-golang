# learning-golang

面向有 Java 后端经验的开发者，这个仓库用于把 Go 学习过程变成一个每天可执行、每周可复盘、每月可验收的学习系统。

当前目标不是"看完很多资料"，而是用 6 到 9 个月，把自己训练到能够胜任 Go 后端岗位的入门到中级要求。学习分阶段推进，每个月有明确目标和验收标准。

## 这个仓库解决什么问题

- 每天打开仓库就知道今天学什么
- 从 Java 经验出发理解 Go，而不是从零散语法点开始
- 用项目驱动学习，避免只学不会用
- 用固定复盘机制控制认知负担，避免学了就忘
- 逐步沉淀面试笔记、坑点、项目经验和阶段成果

## 适合谁

- 有后端开发经验，尤其是 Java 后端
- 目标转 Go 后端开发
- 每天可稳定投入约 2 小时
- 更喜欢先做出东西，再逐步深入原理

## 仓库结构

- `docs/`：学习路线、使用说明、Java 到 Go 映射、项目路线、坑点与复盘方法
- `plans/`：按月和按周拆解的学习计划
- `projects/`：阶段性项目，优先做能写进简历的后端项目
- `exercises/`：针对语法、并发、错误处理、接口等主题的练习
- `demos/`：小型实验代码，验证某个知识点或库的最小示例
- `templates/`：日报、周复盘、项目复盘等模板
- `interview-notes/`：Go 后端面试知识沉淀
- `progress/`：阶段进度、完成定义、学习记录入口
- `assets/`：图片、流程图等静态资源

## 建议使用方式

1. 先阅读 `docs/how-to-use-this-repo.md`，明确每天、每周、每月如何使用这个仓库。
2. 再阅读 `docs/roadmap.md` 和 `docs/project-roadmap.md`，理解学习主线与项目主线。
3. 从 `plans/month-01/README.md` 开始，按周推进第 1 个月内容。
4. 每天完成最小交付：代码、笔记、1 条复盘、1 个问题。
5. 每周用 `docs/review-template.md` 做一次复盘，判断是否进入下一周。

## 第 1 个月的目标

第 1 个月只做四件事：

- 建立 Go 基础开发环境和基本语法能力
- 理解 Go 的核心编码风格和错误处理方式
- 能使用标准库完成基础文件、JSON、HTTP 编程
- 做出一个小型 Todo API，具备路由、参数校验、错误返回、内存存储和基础测试

完成后，你应该能回答这些问题：

- Go 和 Java 在类型、接口、错误处理上的核心差异是什么
- 如何用 Go 写一个最小可维护的 HTTP 服务
- 什么时候用 struct、interface、slice、map、pointer
- 如何组织一个简单 Go 项目的目录和包
- 如何写 table-driven tests

## 第 2 个月的目标

第 2 个月从"能跑"进入"可维护"：

- 理解分层设计与依赖组织
- 引入配置管理和结构化日志
- 接入数据库完成持久化 CRUD
- 实现中间件、context 传递、错误码体系
- 做出一个带数据库的 Blog API 项目

完成后，你应该能回答这些问题：

- handler、service、repository 各层职责是什么，依赖方向怎么走
- 如何在 Go 中接入数据库并处理事务
- context 在请求链路中的作用和使用场景
- 如何写中间件以及中间件的组合方式
- 如何设计统一的错误返回格式

## 阶段完成标准

第 1 个月结束时，至少满足以下条件：

- 独立写出一个可运行的 Go HTTP API
- 能看懂并修改大多数基础 Go 示例代码
- 对常见坑有初步认知，不再机械套用 Java 思维
- 有一份自己的月度复盘和项目复盘记录
- 仓库中至少留下可展示的代码、笔记、计划执行记录

第 2 个月结束时，至少满足以下条件：

- 能独立搭建带数据库的 Go HTTP 服务
- 项目具备清晰的分层结构
- 能写中间件并解释 context 的作用
- Blog API 可完整运行，具备错误处理和日志
- 能对比两个月的项目并说出工程质量上的进步
