# 第 3 个月计划

第 3 个月的目标是掌握 Go 作为后端语言最核心的一块能力：并发与服务治理基础。

前两个月解决的是"能写服务"和"能把服务写得更像工程"，这个月解决的是"能不能把 Go 真正用出差异化价值"。

## 本月目标

本月结束时，你需要达到以下状态：

- 能独立写出常见 goroutine 和 channel 协作代码
- 能解释 channel、mutex、waitgroup、select、context 各自适用场景
- 能识别并修复基础竞态问题、死锁风险和 goroutine 泄露风险
- 能实现一个最小可用的 worker pool 或异步任务处理流程
- 能给服务加上超时、取消、重试、限流等基础治理能力
- 能用 `go test -race`、benchmark、`pprof` 对简单问题做诊断
- 能把第 3 个月项目讲成一个具有 Go 特征的后端项目

## 前置条件

进入第 3 个月前，确认你已满足第 2 个月的验收标准：

- 能独立搭建带数据库的 Go HTTP 服务
- 能解释分层设计和依赖方向
- 能使用 context、日志、中间件、错误码完成基本请求链路
- Blog API 已完成主要功能并具备基础测试

如果第 2 个月还没有真正打通，不要硬切到并发。先把已有项目补齐，否则并发学习会变成只会写 demo，不会落地。

## 本月学习主线

主线：围绕一个"任务处理服务"学习 Go 并发。

不是为了学并发而学并发，而是在服务里逐步引入：

- 先理解并发原语，再写最小并发 demo
- 先做 worker pool，再加超时、取消、重试
- 先能跑通任务流，再做并发安全和性能诊断
- 每周复盘判断是否进入下一周

## 本月项目建议

主项目建议：`projects/month-03-task-worker-service/`

这个项目建议实现以下能力：

- 提交任务接口
- 查询任务状态接口
- 内存版任务队列或简化持久化
- worker pool 消费任务
- 任务超时和取消
- 简单失败重试
- 基础限流或并发数控制

重点不是把系统做大，而是让每个并发机制都能在项目中有真实落点。

## 周计划概览

### Week 1：goroutine、channel、select、waitgroup

目标：建立 Go 并发编程最小心智模型。

交付：

- 并发基础 demo
- channel 和 select 的最小练习
- 能解释同步等待和通信的差异

### Week 2：mutex、竞态条件、worker pool、context

目标：进入真实后端更常见的并发控制方式。

交付：

- mutex 和竞态问题实验
- worker pool demo
- 在任务处理服务中引入 context

### Week 3：超时、取消、重试、限流

目标：把并发能力转成服务治理能力。

交付：

- 任务处理服务支持超时和取消
- 简单重试机制
- 基础限流或并发控制

### Week 4：benchmark、pprof、race detector、项目复盘

目标：建立基础性能意识，并完成第 3 个月项目闭环。

交付：

- 至少 1 个 benchmark
- 至少 1 次 race detector 使用记录
- 至少 1 次 pprof 体验
- 一次项目复盘和月复盘

## 每周完成定义

每周都必须满足：

- 有代码产出
- 有最小可运行示例
- 有至少一次复盘
- 有下周进入条件判断

## 每日执行模板

每天 2 小时建议这样分配：

- 20 分钟：看当天任务和资料
- 70 分钟：编码和实验
- 20 分钟：整理结论和问题
- 10 分钟：安排明天起点

## 本月验收标准

月末时，检查自己是否满足以下条件：

- 能独立写出一个最小 worker pool，并解释它的任务流转
- 能说清 channel 和 mutex 分别适合解决什么问题
- 能演示 `context.WithTimeout` 和 `context.WithCancel` 的实际效果
- 能用 `go test -race` 发现并修复至少 1 个竞态问题
- 能写 1 个 benchmark 并解释结果不能代表什么、能代表什么
- 任务处理服务能跑通任务提交、消费、状态更新的最小闭环
