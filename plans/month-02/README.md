# 第 2 个月计划

第 2 个月的目标是从"能跑"进入"可维护"，写出更像真实后端服务的代码。

## 本月目标

本月结束时，你需要达到以下状态：

- 能独立搭建一个带数据库的 Go CRUD 服务
- 理解分层设计、依赖组织和包划分的基本原则
- 能使用配置文件管理服务参数
- 能接入结构化日志
- 能用中间件处理通用逻辑
- 能正确使用 context 传递超时和取消信号
- 能写出比第 1 个月更规范的错误码和参数校验
- 能完成一个 Blog API 项目并说清设计取舍

## 前置条件

进入第 2 个月前，确认你已满足第 1 个月的验收标准：

- 能独立写出一个最小 HTTP 服务
- 能解释 Go 的错误处理和 Java 的区别
- 能独立完成 Todo API 的主要接口
- 能写基础 table-driven tests

如果以上没有完全通过，先回去补齐，不要急着进入新阶段。

## 本月学习主线

主线：围绕 Blog API 项目，学习后端服务的工程化能力。

不是把所有工具学一遍再做项目，而是在项目推进中逐步引入：

- 先重构分层，再加配置和日志
- 先接数据库，再处理事务和连接池
- 先写中间件，再理解 context 传递
- 每周复盘判断是否进入下一周

## 周计划概览

### Week 1：分层设计、配置管理、结构化日志

目标：把代码从"能跑"升级为"可读可维护"。

交付：

- 重构项目分层结构
- 引入配置文件管理
- 接入结构化日志
- Blog API 项目骨架搭建

### Week 2：数据库接入、SQL 操作、事务

目标：让服务具备真实持久化能力。

交付：

- 接入 PostgreSQL 或 SQLite
- 完成数据库 CRUD 操作
- 理解连接池和事务的基本用法

### Week 3：中间件、context、错误码、参数校验

目标：让服务具备生产级的请求处理能力。

交付：

- 实现日志中间件和恢复中间件
- 用 context 传递请求级信息和超时控制
- 统一错误码返回
- 参数校验机制

### Week 4：完善 Blog API + 测试增强 + 月复盘

目标：形成第二个可展示成果。

交付：

- Blog API 完整 CRUD 和基础功能闭环
- 补充集成测试和 handler 测试
- 做一次项目复盘和月复盘

## 每周完成定义

每周都必须满足：

- 有代码产出
- 有最小可运行示例
- 有至少一次复盘
- 有下周进入条件判断

## 每日执行模板

每天 2 小时建议这样分配：

- 20 分钟：看当天任务和资料
- 70 分钟：编码和实验
- 20 分钟：整理结论和问题
- 10 分钟：安排明天起点

## 本月验收标准

月末时，检查自己是否满足以下条件：

- 能独立搭建带数据库的 Go HTTP 服务
- 能解释分层设计中每层的职责和依赖方向
- 能用配置文件管理数据库连接、端口等参数
- 能写 2 到 3 个中间件并解释其作用
- 能说清 context 在请求链路中的作用
- Blog API 可完整运行，具备基础错误处理和日志
