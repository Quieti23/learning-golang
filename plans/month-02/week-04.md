# Week 4：完善 Blog API、测试增强、月度复盘

## 本周目标

- 完成 Blog API 的功能闭环
- 提升测试覆盖和测试质量
- 做第 2 个月阶段复盘

## 本周交付

- Blog API 完整 CRUD 和基础功能
- service 层和 handler 层测试
- 一次项目复盘
- 一次月复盘

## 建议日程

### Day 1

- 检查 Blog API 功能完整性：创建、查询列表、查询详情、更新、删除
- 补齐遗漏的边界处理：空值、不存在的 ID、重复操作
- 输出：所有接口行为稳定

### Day 2

- 为 service 层写单元测试
- 用 mock 或 fake repository 隔离数据库依赖
- 输出：service 层核心逻辑有测试覆盖

### Day 3

- 为 handler 层写 HTTP 测试
- 用 `httptest.NewRecorder` 测试路由和状态码
- 输出：关键接口有 handler 测试

### Day 4

- 写 1 到 2 个集成测试：从 HTTP 请求到数据库的完整流程
- 输出：能验证一个接口的端到端行为

### Day 5

- 整理代码：清理不合理的命名、重复代码、不一致的风格
- 补充 Blog API 的 README：项目说明、运行方式、接口文档
- 输出：项目可读性提升

### Day 6

- 做项目复盘
- 对比 Todo API 和 Blog API 的差异
- 记录设计取舍、遇到的问题、后续优化点
- 输出：一份项目复盘记录

### Day 7

- 做月复盘
- 判断是否满足进入第 3 个月的条件
- 明确第 3 个月需要重点提升的方向

## 本周完成标准

- Blog API 能跑通完整 CRUD，数据持久化到数据库
- 至少有 5 个有效测试用例
- 项目有基本的 README 和接口说明
- 你能讲清项目的分层设计和每层实现

## 月末判断问题

- 如果面试官问你怎么组织一个 Go 后端项目的分层结构，你能否画出来并解释
- 如果让你在 Go 中接入数据库并处理事务，你能否写出核心代码
- 如果问 context 在 Go 中有什么用，你能否举出至少 3 个场景
- 如果让你写一个中间件，你能否现场实现
- 如果让你对比 Todo API 和 Blog API，你能否说出工程质量上的进步
